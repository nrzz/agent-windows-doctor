# Security policy

## Supported versions

Security fixes go into the latest release on `main`.

## Reporting a vulnerability

Please do not report a vulnerability in a public issue. Use GitHub's private reporting: [https://github.com/nrzz/agent-windows-doctor/security/advisories/new](https://github.com/nrzz/agent-windows-doctor/security/advisories/new), or the contact in the [nrzz security policy](https://github.com/nrzz/.github/blob/main/SECURITY.md). You can expect a first answer within 72 hours, and credit in the release notes if you want it.

## What this tool does, and does not do

It has no telemetry or account and sends nothing to anyone. It has no network code except the local connection of `check --live` (see below). It changes nothing on the computer: there is no command that writes a settings file, the registry, `PATH` or any configuration of an agent.

**It reads.** For each agent, the files that bear on the shell and on hooks, and only for the keys that matter: Claude Code's user, project, local and managed settings (`env`, `defaultShell`, `permissions.deny`, `hooks`, `wslInheritsWindowsSettings`); Codex CLI's `config.toml` (the user's, the system's under `ProgramData`, and a trusted project's) and `hooks.json`, with the `windows`, `features` and `sandbox_mode` keys and the hooks; Gemini CLI's settings (user, project and system) for `hooks`; Copilot CLI's hook files (`COPILOT_HOME\hooks`, `.github\hooks`, the policy folder) and the project's `.claude\settings.json`; Cursor's `hooks.json` files. The registry: the values of `HKCU\Environment` (every name; a value only when its name ends in DIR, PATH, HOME, FILE or ROOT, or the value is a switch such as 1 or false), `LongPathsEnabled`, the code pages, the build and update revision of Windows, the managed settings of Claude Code, and where Git for Windows says it is installed. The folders on PATH and the usual install folders of each agent, to find every binary, launcher and shim, with the `package.json` of an npm package, the version resource of an `.exe`, or the name of a version folder for its version; the Cursor CLI's `agent.cmd` and `cursor-agent.ps1`. The project's `.git\index.lock`. Codex's sandbox log under `CODEX_HOME\.sandbox`. Inside WSL, `/proc/version` and the paths of the config folders. No file is shown whole, and no environment value is printed unless it is a path or a switch: a token in `ANTHROPIC_API_KEY` shows as "set", never its value.

**It starts a few programs, all of which only read:** `where.exe`, `reg.exe query`, `git --version` and `git config --show-origin --get-all`, `powershell.exe` and the first `pwsh.exe` on PATH with `-NoProfile -NonInteractive` (to ask for the edition, the language mode and `Get-ExecutionPolicy -List`, for the version resource of some files, and for the Microsoft Store package `OpenAI.Codex`), `cmd.exe /c chcp`, `tasklist` (only when an `index.lock` exists), `wsl.exe -l -v`, `npm --version` and `npm config get prefix`, and the Git Bash that Claude Code would take with `-c "exit 0"`. `check` never starts an agent. It never runs the desktop app's own launcher, a Microsoft Store alias or the Cursor CLI launcher. A program that has a startup cache of its own (PowerShell, npm) may leave it under your `AppData` or `ProgramData` folder; the tool itself leaves nothing there.

**`check --live` opens one local connection and starts the real agents.** A fake API listens on 127.0.0.1 at a port the system picks, one per agent (the Messages API for Claude Code, the Responses API for Codex CLI, the Gemini API for Gemini CLI, chat completions for Copilot CLI). Before a binary starts, a guard checks that `HOME`, `USERPROFILE`, `LOCALAPPDATA`, `APPDATA`, `CODEX_HOME`, `COPILOT_HOME`, `CLAUDE_CONFIG_DIR` and `GEMINI_CLI_HOME` all name a folder inside a throwaway folder of the system temp folder, in every spelling of the name, and that `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` name a closed port on 127.0.0.1 with `NO_PROXY=127.0.0.1,localhost`; if one does not, nothing starts. The binary gets a dummy key, a throwaway home, config folder and project folder, automatic updates and telemetry switched off, and none of your agent variables (every `CLAUDE_*`, `ANTHROPIC_*`, `CLAUDECODE*`, `OPENAI_*`, `CODEX_*`, `COPILOT_*`, `GEMINI_*` and `CURSOR_*` variable is removed); the rest of your environment, `PATH` first, is kept, because the answer depends on it. For Claude Code only the settings that decide the shell are copied into the throwaway config folder (the `env` entries `CLAUDE_CODE_GIT_BASH_PATH` and `CLAUDE_CODE_USE_POWERSHELL_TOOL`, and the whole-tool deny rules); your hooks, your keys and your other settings are not, so no hook of yours runs. The fake API answers every request with a script (one shell call that prints the PowerShell's own command line, then the text PROBE-DONE), so no model is reached and no token is spent. The binaries are the first of their kind on PATH, or the ones you name with `--claude`, `--codex`, `--gemini` and `--copilot`: they run with your user's rights, as they do when you start them. The throwaway folders are removed afterwards. The Cursor CLI is never run.

The findings are a reading of what the agents did when they were put to the binaries (the README's "What was verified, and how" says which versions) and of what their documentation says; they are not a guard. A wrong verdict is a bug and not a vulnerability: report it as an issue.
